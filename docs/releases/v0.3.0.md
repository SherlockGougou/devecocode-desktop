# DevEco Code Desktop v0.3.0

发布日期：2026-11-23

## 中文

v0.3.0 将 Offline 版内置的 DevEco Code CLI 更新到 `0.2.6`，并同步内置
`@deveco/deveco-cli` / `@deveco/deveco-cli-common` 到 `1.3.12`。桌面端沿用 `0.2.9`
的子代理会话展示与任务对话详情；普通版不内置 CLI。

### 版本内容

- Offline 版固定安装 `@deveco/deveco-code@0.2.6` 及对应 arm64 / x64 平台包，取代此前随
  `v0.2.9` 发布的 `0.2.5`；应用内更新 Offline 版时会同时替换内置 CLI。
- Offline 版显式固定 `@deveco/deveco-cli@1.3.12` 和
  `@deveco/deveco-cli-common@1.3.12`，发布流水线与 CI 的离线资源检查使用同一组版本。
- 保留 `0.2.9` 的子代理会话行为：侧栏只显示根会话，父会话任务面板可在“对话/活动”间
  切换，完整子会话按需加载，实时事件继续更新已打开的对话。
- 同步更新两组 Dependabot 依赖；前端测试 37 项、Rust 测试 114 项通过。

### 升级

`0.2.9` 可以直接通过应用内更新升级到 `0.3.0`；如果更新入口不可用，请手动下载本页
DMG。更早版本仍建议手动安装一次。

本次发布完成后，GitHub Releases 只保留 `v0.3.0`；旧版本不再提供下载。

### 下载

- Apple Silicon：`DevEco.Code_0.3.0_aarch64.dmg`
- Intel：`DevEco.Code_0.3.0_x64.dmg`
- Offline 版：`DevEco.Code.Offline_0.3.0_aarch64.dmg` 和
  `DevEco.Code.Offline_0.3.0_x64.dmg`

普通版需要另行安装并登录 `@deveco/deveco-code`；Offline 版内置 CLI，但仍需要网络登录
和调用模型，内置 CLI 的数据目录独立，升级后需要在内置 CLI 中重新登录一次。更新客户端
会读取 `latest.json` / `latest-offline.json`、`.app.tar.gz` 和 `.sig` 资产。

### 安装

1. 打开 DMG，把 `DevEco Code.app` 或 `DevEco Code Offline.app` 拖入“应用程序”。
2. 当前构建没有 Developer ID 签名，也没有公证；首次打开请右键应用选择“打开”，或到
   “系统设置 → 隐私与安全性”点击“仍要打开”。
3. 普通版首次使用前安装 CLI：

```bash
npm i -g @deveco/deveco-code
deveco providers
```

完整说明见 `docs/installation.md`。

### 校验

Release 附带 `SHA256SUMS.txt`、GitHub artifact attestation 和两套更新清单。下载全部
资产后可以执行：

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.3.0 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.3.0_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

attestation 证明构建来源和资产未被替换，不替代 Apple Developer ID 签名或公证。

### 已知限制

- CLI `0.2.6` 的上游说明仅列出“修复鸿蒙版本若干已知问题”，未公开具体修复清单；本次
  没有对每一项上游变化做端到端回归。
- 子代理对话目前只读，不能直接编辑子代理消息或继续该子会话；需要继续工作时，请在父
  会话里重新发起任务。
- 完整对话按需读取；服务不可用或请求失败时，任务详情显示错误，已缓存的活动摘要仍可
  切换查看。
- 子会话识别依赖 CLI 的 `parentID` 或历史标题标记；两者都缺失的极旧数据仍可能作为
  普通会话显示。
- 仅验证 macOS 12+；不提供 Universal 二进制，也不支持 Windows 或 Linux。
- 发布包仍是 ad-hoc 签名，不是 Apple 可验证身份；更新后 macOS 的文件夹授权可能需要
  重新允许。
- 从 DMG 直接运行、处于 App Translocation 或没有写入权限时无法替换应用，需要先移动到
  “应用程序”。Homebrew cask 的版本记录不会随应用内更新同步。
- 更新下载中不能取消；退出应用会中止下载。更新前正在执行的会话和内存中的排队消息会
  因重启中断。
- DevEco Studio、HarmonyOS SDK、HDC 和模拟器不随应用分发；登录、模型调用和知识库
  仍需要网络。

## English

v0.3.0 updates the CLI bundled in the Offline build to `0.2.6` and pins
`@deveco/deveco-cli` / `@deveco/deveco-cli-common` to `1.3.12`. The desktop behavior from
`0.2.9`, including subagent session filtering and task transcripts, is unchanged. The
Standard build does not bundle the CLI.

### What's new

- The Offline build now pins `@deveco/deveco-code@0.2.6` and the matching arm64/x64
  platform packages, replacing `0.2.5` shipped with `v0.2.9`. Updating the Offline build
  in-app replaces the bundled CLI as well.
- The Offline build explicitly pins `@deveco/deveco-cli@1.3.12` and
  `@deveco/deveco-cli-common@1.3.12`. The release pipeline and CI offline resource job use
  the same versions.
- The `0.2.9` subagent behavior is retained: the sidebar lists only root sessions, the
  parent task panel switches between Conversation and Activity, full child transcripts
  load on demand, and live events keep an open transcript updated.
- Updated two Dependabot dependency groups. The frontend suite has 37 tests and the Rust
  suite has 114 tests.

### Upgrade

`0.2.9` can update to `0.3.0` in-app. If the updater is unavailable, download the DMG from
this release manually. Earlier versions should still perform a one-time manual install.

After this release is published, GitHub Releases will only keep `v0.3.0`; older versions
will no longer be available for download.

### Downloads

- Apple Silicon: `DevEco.Code_0.3.0_aarch64.dmg`
- Intel: `DevEco.Code_0.3.0_x64.dmg`
- Offline: `DevEco.Code.Offline_0.3.0_aarch64.dmg` and
  `DevEco.Code.Offline_0.3.0_x64.dmg`

The Standard build requires a separately installed and signed-in `@deveco/deveco-code`;
the Offline build bundles the CLI but still needs network access for sign-in and model
calls. Its CLI data directory is isolated, so sign in again to the bundled CLI after an
upgrade. The updater reads `latest.json` / `latest-offline.json`, `.app.tar.gz`, and
`.sig` assets.

### Install

1. Open the DMG and drag `DevEco Code.app` or `DevEco Code Offline.app` into Applications.
2. This build is not Developer ID signed or notarized. On first launch, right-click the
   app and choose Open, or use System Settings → Privacy & Security → Open Anyway.
3. For the Standard build, install the CLI first:

```bash
npm i -g @deveco/deveco-code
deveco providers
```

See `docs/installation.md` for the full guide.

### Verify

The release includes `SHA256SUMS.txt`, GitHub artifact attestations, and both updater
manifests. After downloading all assets:

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.3.0 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.3.0_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

Attestations prove build provenance and asset integrity; they do not replace Apple
Developer ID signing or notarization.

### Known limitations

- The upstream CLI changelog for `0.2.6` only says that several HarmonyOS issues were
  fixed; individual upstream changes were not covered by end-to-end regression tests.
- A child transcript is currently read-only. Editing a child message or continuing that
  child session directly is not supported; start a new task from the parent session.
- The full transcript is loaded on demand. If the service is unavailable or the request
  fails, the task detail shows an error and the cached Activity view remains available.
- Subagent detection relies on the CLI `parentID` or the legacy title marker. Very old
  data with neither may still appear as an ordinary session.
- Validated on macOS 12+ only; there is no Universal binary and no Windows or Linux
  support.
- Builds remain ad-hoc signed rather than using a verifiable Apple identity; macOS folder
  permissions may need to be granted again after an update.
- Running directly from the DMG, App Translocation, or a read-only location prevents app
  replacement; move the app to Applications first. Homebrew cask versions do not track
  in-app updates.
- An in-progress update download cannot be cancelled; quitting the app aborts it. Running
  sessions and queued messages are interrupted by the restart.
- DevEco Studio, the HarmonyOS SDK, HDC, and emulators are not bundled; sign-in, model
  calls, and the knowledge base still require network access.
