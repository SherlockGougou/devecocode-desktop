# DevEco Code Desktop v0.2.4

发布日期：2026-11-09

## 中文

v0.2.4 修复普通版从 Finder 启动后无法连接后端的问题，并保留 v0.2.3 的应用内更新、
Homebrew tap、校验和与 artifact attestation。普通版不内置 CLI；Offline 版内置固定版本
CLI。

### 版本内容

- 修复普通版在 Finder / LaunchServices 启动时找不到 Node 的问题：npm / Homebrew 安装的
  `deveco` 是 `#!/usr/bin/env node` 启动器，应用只继承系统 `PATH`
  （`/usr/bin:/bin:/usr/sbin:/sbin`）时无法执行 `serve`，表现为“本地服务已停止 /
  deveco serve 启动后立即退出，输出：（无输出）”。
- 启动 CLI 前现在会把 CLI 自身目录、用户现有 `PATH`、Homebrew / MacPorts / npm /
  pnpm / yarn / volta / bun / asdf / mise 以及 nvm / fnm 版本目录并入子进程 `PATH`；
  `deveco --version` 探测与 `serve` 启动共用同一规则，并保持用户已有 `PATH` 的优先级。
- 启动失败横幅现在同时显示 stdout 和 stderr 尾部，不再隐藏 `env: node: No such file
  or directory` 这类真实原因。
- 新增 `PATH` 顺序与去重单测；在最小系统 `PATH` 下运行完整 `deveco-selftest`。
- v0.2.3 的应用内更新、Homebrew tap、双语 Release notes、`SHA256SUMS.txt` 和
  artifact attestation 保持不变。

### 升级

`0.2.3` 可以直接通过应用内更新升级到 `0.2.4`；如果更新入口不可用，请手动下载本页
DMG。`0.2.2` 及更早版本仍需要手动安装一次。

本次发布完成后，GitHub Releases 只保留 `v0.2.4`；旧版本不再提供下载，避免继续下载到
受影响的 `0.2.3`。

### 下载

- Apple Silicon：`DevEco.Code_0.2.4_aarch64.dmg`
- Intel：`DevEco.Code_0.2.4_x64.dmg`
- Offline 版：`DevEco.Code.Offline_0.2.4_aarch64.dmg` 和
  `DevEco.Code.Offline_0.2.4_x64.dmg`

普通版需要另行安装并登录 `@deveco/deveco-code`；Offline 版内置固定版本 CLI，但仍需要
网络登录和调用模型。更新客户端会读取 `latest.json` / `latest-offline.json`、
`.app.tar.gz` 和 `.sig` 资产。

### 安装

1. 打开 DMG，把 `DevEco Code.app` 或 `DevEco Code Offline.app` 拖入“应用程序”。
2. 当前构建没有 Developer ID 签名，也没有公证；首次打开请右键应用选择“打开”，或到
   “系统设置 → 隐私与安全性”点击“仍要打开”。
3. 普通版首次使用前安装 CLI：

```bash
npm i -g @deveco/deveco-code
deveco providers
```

完整说明见 `docs/installation.md`。

### 校验

Release 附带 `SHA256SUMS.txt`、GitHub artifact attestation 和两套更新清单。下载全部
资产后可以执行：

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.4 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.4_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

attestation 证明构建来源和资产未被替换，不替代 Apple Developer ID 签名或公证。

### 已知限制

- 仅验证 macOS 12+；不提供 Universal 二进制，也不支持 Windows 或 Linux。
- 发布包仍是 ad-hoc 签名，不是 Apple 可验证身份；更新后 macOS 的文件夹授权可能需要
  重新允许。
- 从 DMG 直接运行、处于 App Translocation 或没有写入权限时无法替换应用，需要先移动到
  “应用程序”。Homebrew cask 的版本记录不会随应用内更新同步，可以继续用
  `brew upgrade --cask` 重装。
- 更新下载中不能取消；退出应用会中止下载。更新前正在执行的会话和内存中的排队消息会
  因重启中断。
- DevEco Studio、HarmonyOS SDK、HDC 和模拟器不随应用分发；登录、模型调用和知识库
  仍需要网络。
- 历史消息编辑只支持用户消息及文本/附件内容，发送后不可撤销，文件还原可能覆盖之后的
  未提交修改。

## English

v0.2.4 fixes the Standard build failing to connect to its backend when launched from
Finder, while keeping the in-app updater, Homebrew tap, checksums, and artifact
attestations introduced in v0.2.3. The Standard build does not bundle the CLI; the Offline
build ships a pinned CLI.

### What's new

- Fixed the Standard build not finding Node when launched by Finder / LaunchServices:
  npm / Homebrew installations of `deveco` use a `#!/usr/bin/env node` launcher, and a
  GUI-launched app only inherits the system `PATH`
  (`/usr/bin:/bin:/usr/sbin:/sbin`). `serve` exited immediately, which surfaced as
  “local service stopped / deveco serve exited immediately with no output”.
- Before running the CLI, the app now merges the CLI directory, the existing user `PATH`,
  Homebrew / MacPorts / npm / pnpm / yarn / volta / bun / asdf / mise, and nvm / fnm
  version directories into the child `PATH`. Version probing and `serve` startup use the
  same rule, and existing user `PATH` entries keep their priority.
- Startup failures now show the tail of both stdout and stderr, so errors such as
  `env: node: No such file or directory` are no longer hidden.
- Added unit coverage for `PATH` ordering and deduplication, plus a full
  `deveco-selftest` run under the minimal system `PATH`.
- The in-app updater, Homebrew tap, bilingual release notes, `SHA256SUMS.txt`, and
  artifact attestations from v0.2.3 are unchanged.

### Upgrade

`0.2.3` can update to `0.2.4` in-app. If the updater is unavailable, download the DMG from
this release manually. `0.2.2` and earlier still require a one-time manual install.

After this release is published, GitHub Releases will only keep `v0.2.4`; older versions
will no longer be available for download, so users cannot accidentally install the
affected `0.2.3` build.

### Downloads

- Apple Silicon: `DevEco.Code_0.2.4_aarch64.dmg`
- Intel: `DevEco.Code_0.2.4_x64.dmg`
- Offline: `DevEco.Code.Offline_0.2.4_aarch64.dmg` and
  `DevEco.Code.Offline_0.2.4_x64.dmg`

The Standard build requires a separately installed and signed-in `@deveco/deveco-code`;
the Offline build bundles a pinned CLI but still needs network access for sign-in and
model calls. The updater also reads `latest.json` / `latest-offline.json`, `.app.tar.gz`,
and `.sig` assets.

### Install

1. Open the DMG and drag `DevEco Code.app` or `DevEco Code Offline.app` into Applications.
2. This build is not Developer ID signed or notarized. On first launch, right-click the
   app and choose Open, or use System Settings → Privacy & Security → Open Anyway.
3. For the Standard build, install the CLI first:

```bash
npm i -g @deveco/deveco-code
deveco providers
```

See `docs/installation.md` for the complete guide.

### Verification

Each release includes `SHA256SUMS.txt`, GitHub artifact attestations, and both update
manifests. After downloading all assets:

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.4 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.4_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

Attestations prove the build origin and that assets were not replaced; they do not replace
Apple Developer ID signing or notarization.

### Known limitations

- macOS 12+ only; there is no Universal binary, and Windows/Linux are not supported.
- The release is ad-hoc signed, not an Apple-verifiable identity. macOS folder permissions
  may need to be granted again after an update.
- Updates cannot replace an app running from a DMG, App Translocation, or a read-only
  location; move it to Applications first. Homebrew cask records do not track in-app
  updates; `brew upgrade --cask` remains available.
- Downloads cannot be cancelled; quitting the app aborts the download. Running sessions
  and in-memory queued messages are interrupted by the restart.
- DevEco Studio, the HarmonyOS SDK, HDC, and emulators are not bundled. Sign-in, model
  calls, and the knowledge base still require network access.
- Message editing only covers user messages with text/attachments. It cannot be undone,
  and restoring files may overwrite later uncommitted changes.
