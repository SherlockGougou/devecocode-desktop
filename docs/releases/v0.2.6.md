# DevEco Code Desktop v0.2.6

发布日期：2026-11-11

## 中文

v0.2.6 增加 Agent 提问交互与等待提醒，并修复自动 OAuth 登录的回调生命周期。普通版
不内置 CLI；Offline 版继续内置固定版本 CLI。

### 版本内容

- Agent 调用 `question` 工具等待输入时，底部问答面板会替换 Composer，不再显示原始
  JSON，也不会让用户继续向正在等待回答的 Agent 发送普通消息。Composer 只隐藏不卸载，
  未发送的草稿不会丢失。
- 问答面板支持单题/多题翻页、单选/多选、选项说明、自定义答案、“无偏好”和 `⌘Enter`
  提交，也可以收起面板或从右侧菜单停止当前生成。回答后消息流保留可展开的已回答摘要。
- 打开工作区、切换会话或断线重连时从 `/question` 补齐待答请求，并跟随
  `question.asked/replied/rejected` 实时增删；慢快照会按顺序重放期间的实时变更，避免
  刚出现的问题被清掉或已回答的请求重新出现。空闲、错误和删除会话时会清理该会话的
  待答状态。
- 等待回答期间，窗口标题、侧栏会话行和菜单栏都会显示提醒；菜单栏把待授权和待回答
  合并计数，并在提示中分别列出。系统通知新增“等待你的回答”，与授权一样即使在应用
  前台也会提醒，不受“前台静音”影响；设置页可以单独关闭“需要回答时提醒”。
- 自动 OAuth 回调与账号轮询统一使用 10 分钟等待窗口。回调在打开浏览器前启动，
  用户较慢完成授权也不会因短超时被提前中断；自动登录弹窗新增“检查登录状态”。
- 关闭登录弹窗、离开账号页或开始新的登录会取消在途 OAuth；每次登录使用独立流程标识，
  迟到的回调错误不会写入新的登录会话。
- 增加问题归一化、答案矩阵、快照与实时事件合并的前端测试，以及提问分类、通知文案、
  前台提醒和独立去抖的 Rust 测试与自检。

`0.2.5` 可以直接通过应用内更新升级到 `0.2.6`；如果更新入口不可用，请手动下载本页
DMG。更早版本仍建议手动安装一次。

本次发布完成后，GitHub Releases 只保留 `v0.2.6`；旧版本不再提供下载。

### 下载

- Apple Silicon：`DevEco.Code_0.2.6_aarch64.dmg`
- Intel：`DevEco.Code_0.2.6_x64.dmg`
- Offline 版：`DevEco.Code.Offline_0.2.6_aarch64.dmg` 和
  `DevEco.Code.Offline_0.2.6_x64.dmg`

普通版需要另行安装并登录 `@deveco/deveco-code`；Offline 版内置 CLI，但仍需要网络登录
和调用模型。更新客户端会读取 `latest.json` / `latest-offline.json`、`.app.tar.gz`

### 安装

1. 打开 DMG，把 `DevEco Code.app` 或 `DevEco Code Offline.app` 拖入“应用程序”。
2. 当前构建没有 Developer ID 签名，也没有公证；首次打开请右键应用选择“打开”，或到
   “系统设置 → 隐私与安全性”点击“仍要打开”。
3. 普通版首次使用前安装 CLI：

```bash
npm i -g @deveco/deveco-code

```

完整说明见 `docs/installation.md`。

### 校验

Release 附带 `SHA256SUMS.txt`、GitHub artifact attestation 和两套更新清单。下载全部
资产后可以执行：

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.6 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.6_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

attestation 证明构建来源和资产未被替换，不替代 Apple Developer ID 签名或公证。

### 已知限制

- 仅验证 macOS 12+；不提供 Universal 二进制，也不支持 Windows 或 Linux。
- 发布包仍是 ad-hoc 签名，不是 Apple 可验证身份；更新后 macOS 的文件夹授权可能需要
  重新允许。
- 问答面板依赖 CLI 的 `question` 契约；当前验证环境为 CLI `0.2.5`。通知点击仍只能
  聚焦窗口，不能直接定位到会话或具体问题。
- 自动 OAuth 需要在浏览器中完成授权，最长等待 10 分钟；超时后可以继续在浏览器完成，
  再回到账号页刷新或检查登录状态。
- 从 DMG 直接运行、处于 App Translocation 或没有写入权限时无法替换应用，需要先移动到
  “应用程序”。Homebrew cask 的版本记录不会随应用内更新同步。
- 更新下载中不能取消；退出应用会中止下载。更新前正在执行的会话和内存中的排队消息会
  因重启中断。
- DevEco Studio、HarmonyOS SDK、HDC 和模拟器不随应用分发；登录、模型调用和知识库
  仍需要网络。

## English

v0.2.6 adds Agent question interactions and waiting reminders, and fixes the automatic
OAuth callback lifecycle. The Standard build does not bundle the CLI; the Offline build
continues to ship a pinned CLI.

### What's new

- When an Agent calls the `question` tool and waits for input, a bottom question panel
  replaces the Composer instead of exposing raw JSON or allowing another ordinary prompt
  to the blocked Agent. The Composer is hidden rather than unmounted, so unsent drafts are
  preserved.
- The panel supports single and multiple questions with pagination, single- and
  multi-select options, option descriptions, custom answers, a “no preference” action,
  `⌘Enter` submission, collapsing, and stopping the current generation from its menu.
  Answered requests remain in the transcript as expandable summaries.
- Pending requests are restored from `/question` when opening a workspace, switching
  sessions, or reconnecting, then kept in sync with `question.asked/replied/rejected`.
  Changes received during a slow snapshot are replayed in order, so new questions are not
  discarded and answered requests do not reappear. Idle, error, and session deletion
  clear pending questions for that session.
- The window title, sidebar session row, and menu bar show waiting states while an answer
  is required. The menu bar combines permission and question counts and lists them
  separately in its tooltip. A new “waiting for your answer” notification, like permission
  notifications, is delivered even when the app is focused and is not suppressed by the
  foreground quiet mode. It can be disabled independently in Settings.
- Automatic OAuth callbacks and account polling now share a 10-minute wait window. The
  callback starts before the browser opens, so slower sign-ins are no longer cut off by a
  short timeout. Automatic sign-in dialogs now offer “Check sign-in status”.
- Closing the sign-in dialog, leaving the account page, or starting another sign-in
  cancels the in-flight OAuth flow. Each attempt has its own flow identity, so late
  callback errors cannot overwrite a newer sign-in session.
- Added frontend tests for question normalization, answer matrices, and snapshot/event
  merging, plus Rust tests and selftest coverage for question classification,
  notification text, foreground reminders, and independent debouncing.

### Upgrade

`0.2.5` can update to `0.2.6` in-app. If the updater is unavailable, download the DMG from
this release manually. Earlier versions should still perform a one-time manual install.

After this release is published, GitHub Releases will only keep `v0.2.6`; older versions
will no longer be available for download.

### Downloads

- Apple Silicon: `DevEco.Code_0.2.6_aarch64.dmg`
- Intel: `DevEco.Code_0.2.6_x64.dmg`
- Offline: `DevEco.Code.Offline_0.2.6_aarch64.dmg` and
  `DevEco.Code.Offline_0.2.6_x64.dmg`

The Standard build requires a separately installed and signed-in `@deveco/deveco-code`;
the Offline build bundles the CLI but still needs network access for sign-in and model
calls. The updater reads `latest.json` / `latest-offline.json`, `.app.tar.gz`, and `.sig`
assets.

### Install

1. Open the DMG and drag `DevEco Code.app` or `DevEco Code Offline.app` into Applications.
2. This build is not Developer ID signed or notarized. On first launch, right-click the
   app and choose Open, or use System Settings → Privacy & Security → Open Anyway.
3. For the Standard build, install the CLI first:

```bash
npm i -g @deveco/deveco-code
deveco providers
```

See `docs/installation.md` for the complete guide.

### Verification

Each release includes `SHA256SUMS.txt`, GitHub artifact attestations, and both update
manifests. After downloading all assets:

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.6 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.6_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

Attestations prove the build origin and that assets were not replaced; they do not replace
Apple Developer ID signing or notarization.

### Known limitations

- macOS 12+ only; there is no Universal binary, and Windows/Linux are not supported.
- The release is ad-hoc signed, not an Apple-verifiable identity. macOS folder permissions
  may need to be granted again after an update.
- The question panel depends on the CLI `question` contract; the current verification
  environment is CLI `0.2.5`. Notification clicks can only focus the app, not navigate to
  a session or a specific question.
- Automatic OAuth requires completing authorization in a browser and waits for up to
  10 minutes. After a timeout, finish in the browser and refresh or check sign-in status
  on the account page.
- Updates cannot replace an app running from a DMG, App Translocation, or a read-only
  location; move it to Applications first. Homebrew cask records do not track in-app
  updates.
- Downloads cannot be cancelled; quitting the app aborts the download. Running sessions
  and in-memory queued messages are interrupted by the restart.
- DevEco Studio, the HarmonyOS SDK, HDC, and emulators are not bundled. Sign-in, model
  calls, and the knowledge base still require network access.
