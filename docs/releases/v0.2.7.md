# DevEco Code Desktop v0.2.7

发布日期：2026-11-11

## 中文

v0.2.7 改进服务协议更新后的恢复流程，并修正 Agent 问答与消息编辑的交互细节。普通版
不内置 CLI；Offline 版继续内置固定版本 CLI。

### 版本内容

- 服务协议更新或本地同意状态需要复核时，聊天区不再只显示原始错误，而是提示重新阅读
  并同意，并提供“查看并同意”入口直接打开账号设置。
- 账号页会识别服务端返回的 `review_required` 状态，显示“需重新同意”，接受协议时提交
  当前协议版本与 service revision，并区分保存中、等待同步和失败状态。
- 已接受协议但服务端同步未完成时，账号页可以重试同步；同步任务执行期间相关按钮会锁定，
  避免重复提交。
- Agent 问答在模型漏掉 `multiple`、但题干明确标注“可多选”等文字时按多选渲染；显式
  `multiple` 字段始终优先。单选题选中后自动进入下一题，末题、单题和多选题都不会自动
  提交。
- 编辑历史用户消息时会把完整编辑区滚动到视口内，底部操作按钮不再落到视口外；短消息的
  操作按钮在指针向下移动时保持显示。
- 增加协议状态、问答多选推断和自动翻页测试，前端测试共 17 项。

### 升级

`0.2.6` 可以直接通过应用内更新升级到 `0.2.7`；如果更新入口不可用，请手动下载本页
DMG。更早版本仍建议手动安装一次。

本次发布完成后，GitHub Releases 只保留 `v0.2.7`；旧版本不再提供下载。

### 下载

- Apple Silicon：`DevEco.Code_0.2.7_aarch64.dmg`
- Intel：`DevEco.Code_0.2.7_x64.dmg`
- Offline 版：`DevEco.Code.Offline_0.2.7_aarch64.dmg` 和
  `DevEco.Code.Offline_0.2.7_x64.dmg`

普通版需要另行安装并登录 `@deveco/deveco-code`；Offline 版内置 CLI，但仍需要网络登录
和调用模型。更新客户端会读取 `latest.json` / `latest-offline.json`、`.app.tar.gz`
和 `.sig` 资产。

### 安装

1. 打开 DMG，把 `DevEco Code.app` 或 `DevEco Code Offline.app` 拖入“应用程序”。
2. 当前构建没有 Developer ID 签名，也没有公证；首次打开请右键应用选择“打开”，或到
   “系统设置 → 隐私与安全性”点击“仍要打开”。
3. 普通版首次使用前安装 CLI：

```bash
npm i -g @deveco/deveco-code
deveco providers
```

完整说明见 `docs/installation.md`。

### 校验

Release 附带 `SHA256SUMS.txt`、GitHub artifact attestation 和两套更新清单。下载全部
资产后可以执行：

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.7 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.7_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

attestation 证明构建来源和资产未被替换，不替代 Apple Developer ID 签名或公证。

### 已知限制

- 仅验证 macOS 12+；不提供 Universal 二进制，也不支持 Windows 或 Linux。
- 发布包仍是 ad-hoc 签名，不是 Apple 可验证身份；更新后 macOS 的文件夹授权可能需要
  重新允许。
- 重新同意服务协议依赖本机 CLI 与网络同步；如果服务端仍返回 `review_required` 或同步
  长时间未完成，需要恢复网络后重试，完成后才能继续发送请求。
- 问答面板依赖 CLI 的 `question` 契约；当前验证环境为 CLI `0.2.5`。通知点击仍只能
  聚焦窗口，不能直接定位到会话或具体问题。
- 从 DMG 直接运行、处于 App Translocation 或没有写入权限时无法替换应用，需要先移动到
  “应用程序”。Homebrew cask 的版本记录不会随应用内更新同步。
- 更新下载中不能取消；退出应用会中止下载。更新前正在执行的会话和内存中的排队消息会
  因重启中断。
- DevEco Studio、HarmonyOS SDK、HDC 和模拟器不随应用分发；登录、模型调用和知识库
  仍需要网络。

## English

v0.2.7 improves recovery after product agreement changes and fixes interaction details in
Agent questions and message editing. The Standard build does not bundle the CLI; the
Offline build continues to ship a pinned CLI.

### What's new

- When the product agreement changes or the local acceptance state needs review, the chat
  area now explains the required action instead of exposing only the raw error. A
  “Review and accept” action opens account settings directly.
- Account settings recognize the server's `review_required` state, show “Review required,”
  and submit the current agreement version plus service revision when accepting. Saving,
  pending synchronization, and failure states are distinguished.
- If acceptance was stored locally but server synchronization is incomplete, account
  settings can retry it. Related actions remain disabled while synchronization is running
  to prevent duplicate submissions.
- Agent questions now render as multi-select when the model omits `multiple` but explicitly
  labels the question as “select multiple” or equivalent. An explicit `multiple` field
  still wins. Selecting a single-choice answer advances to the next question, but the last,
  single, and multiple-choice questions never submit automatically.
- Editing a historical user message now scrolls the full editor into view so its bottom
  actions remain reachable. Action buttons on short user messages stay visible while the
  pointer moves toward them.
- Added tests for agreement states, inferred multi-select questions, and automatic page
  advancement; the frontend suite now has 17 tests.

### Upgrade

`0.2.6` can update to `0.2.7` in-app. If the updater is unavailable, download the DMG from
this release manually. Earlier versions should still perform a one-time manual install.

After this release is published, GitHub Releases will only keep `v0.2.7`; older versions
will no longer be available for download.

### Downloads

- Apple Silicon: `DevEco.Code_0.2.7_aarch64.dmg`
- Intel: `DevEco.Code_0.2.7_x64.dmg`
- Offline: `DevEco.Code.Offline_0.2.7_aarch64.dmg` and
  `DevEco.Code.Offline_0.2.7_x64.dmg`

The Standard build requires a separately installed and signed-in `@deveco/deveco-code`;
the Offline build bundles the CLI but still needs network access for sign-in and model
calls. The updater reads `latest.json` / `latest-offline.json`, `.app.tar.gz`, and `.sig`
assets.

### Install

1. Open the DMG and drag `DevEco Code.app` or `DevEco Code Offline.app` into Applications.
2. This build is not Developer ID signed or notarized. On first launch, right-click the
   app and choose Open, or use System Settings → Privacy & Security → Open Anyway.
3. For the Standard build, install the CLI first:

```bash
npm i -g @deveco/deveco-code
deveco providers
```

See `docs/installation.md` for the complete guide.

### Verification

Each release includes `SHA256SUMS.txt`, GitHub artifact attestations, and both update
manifests. After downloading all assets:

```bash
shasum -a 256 -c SHA256SUMS.txt
gh release verify v0.2.7 -R SherlockGougou/devecocode-desktop
gh attestation verify "DevEco.Code_0.2.7_aarch64.dmg" -R SherlockGougou/devecocode-desktop
```

Attestations prove the build origin and that assets were not replaced; they do not replace
Apple Developer ID signing or notarization.

### Known limitations

- macOS 12+ only; there is no Universal binary, and Windows/Linux are not supported.
- The release is ad-hoc signed, not an Apple-verifiable identity. macOS folder permissions
  may need to be granted again after an update.
- Reaccepting the product agreement depends on the local CLI and network synchronization.
  If the server continues to return `review_required` or synchronization remains
  incomplete, restore network access and retry before sending requests.
- The question panel depends on the CLI `question` contract; the current verification
  environment is CLI `0.2.5`. Notification clicks can only focus the app, not navigate to
  a session or a specific question.
- Updates cannot replace an app running from a DMG, App Translocation, or a read-only
  location; move it to Applications first. Homebrew cask records do not track in-app
  updates.
- Downloads cannot be cancelled; quitting the app aborts the download. Running sessions
  and in-memory queued messages are interrupted by the restart.
- DevEco Studio, the HarmonyOS SDK, HDC, and emulators are not bundled. Sign-in, model
  calls, and the knowledge base still require network access.
