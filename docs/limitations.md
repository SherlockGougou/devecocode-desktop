# 已知限制

项目仍处于早期 `0.x` 阶段。以下限制来自当前实现和已验证环境，发布说明不应把它们描述成
已完成能力。

## 平台与分发

- **仅验证 macOS。** `tauri.conf.json` 的最低系统版本为 12.0；Windows 需要替换通知、
  菜单栏和部分 CLI 发现逻辑，尚未支持。
- **没有 Universal 二进制。** 当前主要验证 Apple Silicon；Intel Mac 尚未逐项测试。
- **没有 Developer ID 签名和公证。** 发布包使用 ad-hoc 签名（`signingIdentity: "-"`），
  不是 Apple 可验证身份；其他 Mac 首次打开仍可能触发 Gatekeeper 提示。安装说明见
  [macOS 安装与使用](installation.md)。
- **没有自动更新。** 版本升级需要重新构建或下载新的 `.app`，Tauri updater 尚未接入。
- **不打包 CLI。** 用户必须先安装并登录 `@deveco/deveco-code`；应用只驱动本机已存在的实例。
- **不支持多 Tab。** 这是明确的产品决策，不是待实现功能。

## CLI 与系统状态

- 锁屏或屏幕休眠时，CLI 的版本探测和会话 API 可能阻塞。解锁后恢复；应用会给出可读错误，
  但自愈无法在锁屏状态下完成。
- 权限审批需要 CLI 侧 `permission: ask`。当本机策略为 `allow` 时不会出现审批卡片。
- 通知点击只能聚焦主窗口，不能直接跳到会话，也不能在通知内批准权限。
- 通知在勿扰模式和锁屏下的表现仍需人工确认。
- 菜单栏生成中、等待授权、重连、故障四类动态状态主要覆盖状态映射与单测，没有逐状态触发
  真实 SSE 截图。

## 界面与持久化

- 主题、字体、侧栏宽度、模型可见性和隐藏工作区等纯 UI 偏好保存在 localStorage；重装应用
  或清空 WebView 数据后会恢复默认。
- 工作区隐藏名单只存在本地，不修改 CLI 的 `/project` 注册表；清空本地数据后历史目录会再次
  出现。
- 顶栏拖动由前端按帧设置窗口位置，没有系统级贴边分屏和跨 Space 拖动；多显示器与 Retina
  混插尚未实测。
- Office、iWork、HEIC 等文件只能通过 Quick Look 查看首屏缩略图，不解析完整文档结构。
- 超过约 60MB 的二进制附件不会在主线程解码，避免大视频卡住界面。

## 设备能力

- 设备截图要求开发者模式、USB/无线调试和 HDC 授权。
- 当前只支持单帧刷新和截图，不包含实时投屏、触摸注入或按键注入；实测约 0.6 秒/帧。
- 锁屏、安全窗口和受保护内容可能无法抓取像素。
- “充电时保持亮屏”只在应用运行期间生效；异常退出可能留下设备亮屏，重新打开应用并关闭开关
  即可释放。

## 构建与权限

- 重建 debug 包可能改变 ad-hoc 签名，使 macOS 的文件夹授权记录失效，需要重新允许。
- 无文件夹权限时 CLI 仍可能高 CPU 扫描，这是 CLI 自身行为。可用
  `tccutil reset SystemPolicyDocumentsFolder com.deveco.desktop` 重置后重新授权。
- 应用当前没有设置 CSP。发布前应对构建产物收紧 CSP，并重新审查 Tauri capabilities；
  在完成前不要加载不可信远程页面或引入新的 HTML 注入点。

## 明确不做

- 不实现或打包 Agent/CLI 能力；
- 不解析 `~/.local/share/deveco/*.db`；
- 不直接修改 `~/.config/deveco/deveco.jsonc`；
- 不为单个工作区提供多 Tab；
- 不把未执行的测试、未连接的真机或未检查的主题写成已验证。
