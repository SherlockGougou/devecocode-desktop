# 已知限制

项目仍处于早期 `0.x` 阶段。以下限制来自当前实现和已验证环境，发布说明不应把它们描述成
已完成能力。

## 平台与分发

- **仅验证 macOS。** `tauri.conf.json` 的最低系统版本为 12.0；Windows 需要替换通知、
  菜单栏和部分 CLI 发现逻辑，尚未支持。
- **没有 Universal 二进制。** 当前主要验证 Apple Silicon；Intel Mac 尚未逐项测试。
- **没有 Developer ID 签名和公证。** 发布包使用 ad-hoc 签名（`signingIdentity: "-"`），
  不是 Apple 可验证身份；其他 Mac 首次打开仍可能触发 Gatekeeper 提示。安装说明见
  [macOS 安装与使用](installation.md)。
- **应用内更新依赖 GitHub Releases。** 普通版与 Offline 版分别读取两套静态清单；更新包
  使用自建 Ed25519 签名，不是 Apple Developer ID。首个带更新功能的版本发布前，0.2.2 及
  更早版本仍需手动安装一次。
- **更新后可能需要重新授权。** 发布包仍是 ad-hoc 签名，替换应用后 macOS 的文件夹授权
  可能失效，需要在系统提示中重新允许。
- **只读位置无法替换应用。** 从 DMG 直接运行、App Translocation 或没有写入权限时，更新
  会失败；需要先把应用拖入“应用程序”。Homebrew cask 的版本记录不会随应用内更新同步，
  但可以继续用 `brew upgrade --cask` 重装。
- **普通版不打包 CLI。** 用户必须先安装并登录 `@deveco/deveco-code`；Offline 版使用内置
  固定版本 CLI。
- **不支持多 Tab。** 这是明确的产品决策，不是待实现功能。

## 离线版

- Offline 版只解决“安装时不依赖全局 CLI/Node”，不解决模型、登录和 HarmonyOS 知识库的
  网络依赖。
- 内置 CLI 固定为打包时的版本，不跟随系统 `deveco upgrade`；升级 CLI 需要重新发布桌面端。
- 内置 CLI 的配置、数据库和认证位于应用数据目录，和系统 CLI 隔离，首次使用需要重新登录。
- 内置 CLI 不包含 DevEco Studio、HarmonyOS SDK、HDC 和模拟器；构建、运行和部分设备能力仍
  需要这些外部工具。
- 当前离线包体积约 281MiB `.app` / 119MiB `.dmg`（arm64）；x64 会不同。
- 尚无无 Node 的干净 Mac 上完整跑通 Agent 工具链的验收记录；核心 `serve` 已用内置二进制
  在隔离环境中启动成功。

## CLI 与系统状态

- 锁屏或屏幕休眠时，CLI 的版本探测和会话 API 可能阻塞。解锁后恢复；应用会给出可读错误，
  但自愈无法在锁屏状态下完成。
- 权限审批需要 CLI 侧 `permission: ask`。当本机策略为 `allow` 时不会出现审批卡片。
- CLI 进程被强制结束时，持久化的工具调用可能停在 `running`；桌面端只在展示层标记为
  “已中断”，不会回写 CLI 存储，外部客户端仍可能显示运行中。
- 排队与引导只保存在内存中，退出应用后会丢失；队列最多 20 条、附件总量 64MB。
- 引导消息不会硬中断当前模型输出或正在执行的工具，只在下一个模型步骤生效；若当前轮
  已经结束，会作为一条不可见 synthetic 继续消息开启新一轮。
- CLI 0.2.5 的 v2 `/api/session/:id/prompt` 在当前 serve 中未接通执行层，因此不使用
  `delivery: steer|queue` 原生能力；后续 CLI 接通后再评估迁移。
- 通知点击只能聚焦主窗口，不能直接跳到会话，也不能在通知内批准权限。
- 通知在勿扰模式和锁屏下的表现仍需人工确认。
- 菜单栏生成中、等待授权、重连、故障四类动态状态主要覆盖状态映射与单测，没有逐状态触发
  真实 SSE 截图。

## 界面与持久化

- 主题、字体、侧栏宽度、模型可见性、隐藏工作区和未读会话标记等纯 UI 偏好保存在
  localStorage；重装应用或清空 WebView 数据后会恢复默认。
- 工作区隐藏名单只存在本地，不修改 CLI 的 `/project` 注册表；清空本地数据后历史目录会再次
  出现。
- 顶栏拖动由前端按帧设置窗口位置，没有系统级贴边分屏和跨 Space 拖动；多显示器与 Retina
  混插尚未实测。
- Office、iWork、HEIC 等文件只能通过 Quick Look 查看首屏缩略图，不解析完整文档结构。
- 超过约 60MB 的二进制附件不会在主线程解码，避免大视频卡住界面。
- 底部终端依赖 CLI 的 `/pty` 契约；当前只验证 CLI 0.2.5。每次只保留一个终端，关闭面板会
  结束对应 shell，不提供多标签、分屏或后台保活会话。
- 历史消息编辑只支持用户消息，且非 synthetic part 必须是文本或附件；内联编辑器不提供
  @ 弹层和新增附件。会话执行中或有排队/待确认消息时不能编辑。
- 重新发送会永久删除被编辑消息及其后的消息，不保证退还已消耗的 token/费用；编辑首条消息
  不保证自动重命名已有会话。CLI `revert` 会还原工作区，可能覆盖该消息之后的未提交修改。
- 旧版 CLI 如果没有 `revert`/`unrevert` 接口，编辑提交会报错；当前只验证 CLI 0.2.5。

## CLI 配置

- 保存全局或项目配置会重载 CLI 实例，正在运行的任务可能被中断；界面会二次确认，但不能
  保证任务可恢复。
- 项目作用域必须先选择工作区；没有工作区时只能编辑全局配置。
- 表单覆盖常用字段和所有顶层字段的入口；非常复杂或废弃的子字段通过高级 JSONC 编辑，
  不保证每个子字段都有可视化控件。
- 密钥默认脱敏；高级编辑器可以显式显示明文，截图或录屏前需要切回隐藏。配置文件本身无法
  被 JSONC 解析时，界面无法可靠脱敏，会标记“无法脱敏”并按原文本展示以便修复。
- 配置写入会生成应用数据目录下的备份，恢复备份会覆盖当前文件，并在覆盖前再生成一份备份。
- 文件型 Agent/Command 只读；Plugin 只编辑配置入口，不执行 npm 安装。

## 设备能力

- 设备截图要求开发者模式、USB/无线调试和 HDC 授权。
- 桌面端“设备”面板只支持单帧刷新和截图，不包含实时投屏；实测约 0.6 秒/帧。
- Agent 设备 skill 通过 HDC 提供截图、布局树、点击/滑动/文本输入、安装启动和日志采集，
  但不是实时投屏，也不能保证覆盖锁屏、安全窗口或受保护内容。
- 锁屏、安全窗口和受保护内容可能无法抓取像素。
- “充电时保持亮屏”只在应用运行期间生效；异常退出可能留下设备亮屏，重新打开应用并关闭开关
  即可释放。
- 内嵌设备 skill 只在 CLI 启动时扫描；复用已有外部 serve 实例时，需要重启服务才能让新增
  或更新的 skill 生效。

## 构建与权限

- 重建 debug 包可能改变 ad-hoc 签名，使 macOS 的文件夹授权记录失效，需要重新允许。
- 无文件夹权限时 CLI 仍可能高 CPU 扫描，这是 CLI 自身行为。可用
  `tccutil reset SystemPolicyDocumentsFolder com.deveco.desktop` 重置后重新授权。
- 应用当前没有设置 CSP。发布前应对构建产物收紧 CSP，并重新审查 Tauri capabilities；
  在完成前不要加载不可信远程页面或引入新的 HTML 注入点。

## 明确不做

- 不重写 Agent/CLI 能力；普通版不打包 CLI，Offline 版只内置固定版本；
- 不解析 `~/.local/share/deveco/*.db`；
- 不执行 Plugin 的 npm 安装，不编辑文件型 Agent/Command 的 Markdown；
- 不为单个工作区提供多 Tab；
- 不把未执行的测试、未连接的真机或未检查的主题写成已验证。
